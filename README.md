# Лабораторные работы по новым языкам программирования

План лабораторных включает 20 заданий на 20 разных языках, по четыре задания
на каждую из пяти тем. Команды запуска текущих программ приведены в README
соответствующих каталогов.

## План на согласование

### 1.1. Ada — параллельная проверка латинского квадрата

- **Входные данные.** Текстовый файл. В первой строке задан порядок квадрата
  `N`, далее следуют `N` строк по `N` целых чисел.
- **Результат.** Программа сообщает, является ли матрица латинским квадратом.
  Для этого числа от `1` до `N` должны встречаться ровно по одному разу
  в каждой строке и каждом столбце.
- **Основные требования.** Проверить размеры матрицы. Одной задаче Ada поручить
  проверку всех строк, другой — проверку всех столбцов. Дождаться обеих задач
  и объединить их результаты.

### 1.2. D — сравнение последовательного и параллельного расчёта

- **Входные данные.** Положительная целая верхняя граница `N` в аргументах
  командной строки. По умолчанию используется `50 000 000`.
- **Результат.** Сумма квадратных корней чисел от `1` до `N`, время каждого
  расчёта в миллисекундах и количество потоков.
- **Основные требования.** Вычислить одну и ту же сумму обычным циклом и
  параллельно через `taskPool.reduce`. Измерить время каждого варианта отдельно.

### 1.3. Elixir — сбор результатов от процессов

- **Входные данные.** Положительное целое число `N` в аргументах командной
  строки. По умолчанию используется `10`.
- **Результат.** Сумма квадратов чисел от `1` до `N`. Например, при `N = 3`
  программа выводит `14`.
- **Основные требования.** Запустить отдельный процесс Elixir для каждого
  числа. Каждый процесс вычисляет квадрат и отправляет его сообщением.
  Главный процесс принимает `N` результатов и складывает их.

### 1.4. F# — сводка температур по метеостанциям

- **Входные данные.** Пути к двум или более текстовым файлам. Каждый файл
  содержит показания одной станции, по одной целой температуре в градусах
  Цельсия на строку.
- **Результат.** Для каждой станции программа выводит имя файла, количество
  показаний, минимальную, максимальную и среднюю температуру.
- **Основные требования.** Каждый файл читается и обрабатывается в отдельной
  задаче. Главный поток ждёт завершения задач и выводит сводки в порядке
  переданных файлов. Для пустого файла или неверного показания программа
  выводит сообщение с именем файла.

### 2.1. Haskell — раскрытие вложенных повторов команд

- **Входные данные.** Строка из команд `F`, `L` и `R`. Запись `N[...]`
  повторяет блок `N` раз, где `N` — положительное целое число. Внутри блока
  могут быть другие повторы.
- **Результат.** Программа выводит полную последовательность команд.
  Например, из `2[F3[LR]]` получается `FLRLRLRFLRLRLR`.
- **Основные требования.** Разбирать вложенные блоки рекурсивно, сохраняя
  порядок команд. При неизвестной команде, неверном числе повторов или
  несогласованных скобках выводить сообщение об ошибке.

### 2.2. Julia — подсчёт островов

- **Входные данные.** Матрица символов `0` и `1`, где `0` обозначает воду,
  а `1` — сушу. Пример матрицы задан в программе.
- **Результат.** Количество островов. Пример в программе содержит два острова.
- **Основные требования.** Считать соседними клетки с общей стороной. При
  обнаружении суши рекурсивно обходить её непосещённых соседей, чтобы учесть
  каждую связную область один раз.

### 2.3. Kotlin — максимальная глубина бинарного дерева

- **Входные данные.** Корень бинарного дерева, заданного в программе. У каждого
  узла могут быть левый и правый потомки.
- **Результат.** Число узлов на самом длинном пути от корня до листа. Для пустого
  дерева глубина равна `0`, для дерева из примера — `3`.
- **Основные требования.** Рекурсивно вычислять глубину обоих поддеревьев и
  добавлять `1` к большей из двух глубин.

### 2.4. Standard ML — способы подъёма по лестнице

- **Входные данные.** Число ступеней `n`. За один шаг можно подняться на одну
  или две ступени. Для демонстрации программа использует `n = 5`.
- **Результат.** Количество способов добраться до верхней ступени. Для пяти
  ступеней получается восемь способов.
- **Основные требования.** Вычислять ответ рекурсивно по числу оставшихся
  ступеней и сохранять промежуточные результаты в массиве. Для нуля и одной
  ступени есть по одному способу.

### 3.1. Groovy — оглавление Markdown-файла

- **Входные данные.** Путь к Markdown-файлу в UTF-8 и путь к выходному
  текстовому файлу.
- **Результат.** Одна строка оглавления на каждый заголовок. В строке указаны
  номер строки исходного файла, уровень заголовка и его название. Например,
  для `## Запуск` на пятой строке программа записывает `5 — 2 — Запуск`.
- **Основные требования.** Читать файл построчно и сохранять порядок
  заголовков. Учитывать заголовки, начинающиеся с одного–шести символов `#`
  и пробела. Пропускать строки внутри блоков кода, ограниченных тройными
  обратными кавычками.

### 3.2. Lua — добавление и просмотр заметок

- **Входные данные.** Путь к файлу заметок и команда `add` с текстом заметки
  или команда `list`.
- **Результат.** `add` дописывает заметку в файл и выводит подтверждение.
  `list` выводит строки файла с номерами, начиная с `1`.
- **Основные требования.** Открывать файл на добавление или чтение в зависимости
  от команды. При ошибке открытия выводить сообщение.

### 3.3. Perl — сравнение остатков товаров

- **Входные данные.** Пути к двум текстовым файлам с остатками до и после
  обновления. В каждой строке указаны артикул и целое неотрицательное
  количество через пробел. В каждом файле артикул встречается один раз.
- **Результат.** В консоли выводится отчёт о добавленных, удалённых и
  изменившихся позициях. Для изменившейся позиции показываются оба количества.
  Например, если `A101 5` стало `A101 8`, отчёт показывает `A101 — 5 → 8`.
- **Основные требования.** Сравнивать записи по артикулу независимо от порядка
  строк в файлах. Совпадающие позиции пропускать. В каждой группе отчёта
  выводить позиции в порядке артикулов.

### 3.4. Ruby — копирование файла с нумерацией строк

- **Входные данные.** Пути к исходному и выходному текстовым файлам.
- **Результат.** Копия с номерами строк и количество скопированных строк
  в консоли.
- **Основные требования.** Читать исходный файл построчно в UTF-8, сохранять
  порядок строк и добавлять номер перед каждой строкой, начиная с `1`.

### 4.1. Nim — TCP-сервис медианы

- **Входные данные.** Клиент подключается к TCP-серверу и отправляет по одной
  команде на строку. `ADD <число>` добавляет целое число, а `MEDIAN` запрашивает
  медиану накопленных чисел.
- **Результат.** Сервер подтверждает добавление ответом `OK`, а на `MEDIAN`
  возвращает медиану. Например, после `ADD 7` и `ADD 2` ответ на `MEDIAN` —
  `4.5`.
- **Основные требования.** Хранить числа отдельно для каждого подключения.
  Для нечётного количества брать центральное число в отсортированном списке,
  для чётного — среднее двух центральных. Если список пуст или команда
  неверна, возвращать сообщение об ошибке.

### 4.2. Objective-C — HTTP-клиент для расчёта корзины

- **Входные данные.** Список позиций корзины. Для каждой позиции указаны
  цена за единицу в копейках (`price_kopecks`) и количество (`quantity`).
- **Результат.** Клиент выводит итоговую стоимость из ответа сервера. Например,
  для двух товаров по 150 копеек и одного за 230 копеек итог — 530 копеек.
- **Основные требования.** Клиент отправляет позиции в формате JSON запросом
  `POST /checkout`. Локальный тестовый сервер умножает цену каждой позиции на
  количество, складывает результаты и возвращает сумму в поле `total_kopecks`
  ответа JSON. При сбое запроса, неуспешном статусе HTTP или некорректном
  ответе клиент выводит сообщение об ошибке.

### 4.3. Rust — вычисление квадрата числа по TCP

- **Входные данные.** Адрес TCP-сервера и целое число в диапазоне `i64`.
  Клиент отправляет число в виде текстовой строки.
- **Результат.** Сервер возвращает квадрат числа, а клиент выводит ответ
  в консоль. Например, на запрос `12` сервер отвечает `144`.
- **Основные требования.** Обрабатывать каждое подключение в отдельном потоке.
  Возвращать сообщение об ошибке, если запрос не разбирается как `i64`
  или квадрат числа выходит за пределы этого типа.

### 4.4. Swift — TCP-сервер ведения турнирной таблицы

- **Входные данные.** Клиент отправляет по TCP команду `RESULT <команда1>
  <команда2> <счёт1> <счёт2>` для добавления результата матча или `TABLE`
  для просмотра таблицы. Имена команд задаются без пробелов, счёт — целыми
  неотрицательными числами.
- **Результат.** На `RESULT` сервер отвечает `OK` или `ERROR`. На `TABLE`
  сервер возвращает список команд с количеством сыгранных матчей и очками.
- **Основные требования.** Хранить данные в памяти между подключениями.
  Начислять три очка за победу, одно за ничью и ноль за поражение.
  Сортировать команды по убыванию очков, а при равенстве — по имени.
  Отклонять запросы с неверным форматом или одинаковыми именами команд.

### 5.1. Mojo — конвертация файла локализации PO в JSON

- **Входные данные.** Пути к исходному файлу `.po` в UTF-8 и выходному файлу
  `.json`. В файле используются записи `msgid` и `msgstr` без контекста и
  множественных форм.
- **Результат.** JSON-объект, где исходная строка служит ключом, а перевод —
  значением. Например, из `msgid "Save"` и `msgstr "Сохранить"` получается
  `{"Save": "Сохранить"}`.
- **Основные требования.** Разбирать пары `msgid` и `msgstr`, объединять строки
  продолжения, пропускать комментарии и служебный заголовок с пустым `msgid`.
  Экранировать специальные символы при записи JSON.
  [Формат PO](https://www.gnu.org/software/gettext/manual/gettext.html)

### 5.2. Odin — преобразование изображения из PPM P3 в XPM

- **Входные данные.** Пути к текстовому файлу PPM (`P3`) и выходному файлу
  `.xpm`. Максимальное значение цветового канала во входном файле равно `255`.
- **Результат.** XPM-изображение с теми же размерами и цветами. Например,
  тройка `255 0 0` записывается в таблицу цветов как `#FF0000`.
- **Основные требования.** Читать размеры и тройки RGB, пропуская комментарии
  и пробельные символы между значениями. Назначать каждому уникальному цвету
  свой код. Записывать заголовок XPM, таблицу цветов и строки пикселей.
  Все коды цветов в одном файле должны быть одинаковой длины.
  [Формат PPM](https://netpbm.sourceforge.net/doc/ppm.html), [формат XPM](https://www.x.org/docs/XPM/xpm.pdf)

### 5.3. Scala — экспорт расписания в iCalendar

- **Входные данные.** Пути к исходному TSV и выходному файлу `.ics`. Каждая
  строка TSV содержит название события, начало и окончание, разделённые
  табуляцией. Время задано в UTC, например `2026-12-01T10:00:00Z`.
- **Результат.** Календарь iCalendar с одним событием на каждую запись TSV.
  При импорте в календарь сохраняются названия и интервалы событий.
- **Основные требования.** Проверять корректность времени и порядок начала
  и окончания. Записывать события как `VEVENT` с `SUMMARY`, `DTSTART`,
  `DTEND`, `DTSTAMP` и уникальным `UID`. Соблюдать формат дат и экранировать
  специальные символы в названиях. [Спецификация iCalendar](https://www.rfc-editor.org/rfc/rfc5545.html)

### 5.4. Zig — преобразование записей в CSV

- **Входные данные.** Путь к текстовому файлу с блоками записей. Поля записаны
  отдельными строками в виде `ключ=значение`, блоки разделены пустой строкой.
  Поля идут в одном порядке, значения даны без запятых и кавычек.
- **Результат.** CSV выводится в консоль. Первая строка содержит имена полей,
  за ней идут значения каждой записи.
- **Основные требования.** Взять заголовок из ключей первого блока и сохранить
  порядок значений и записей при выводе.
